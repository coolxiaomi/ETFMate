# 条件单执行类型与平台参数映射

核验日期：2026-09-08。资料来自 Touker／华宝智投官方公开手册，通过 `web-access` 读取。本次没有操作用户原有 Touker 标签，也没有新建、修改或提交真实条件单。

用户已确认只使用条件单交易，成交会自动同步同花顺账本。报告应输出可对应平台字段的条件单方案；不能把「另行交易」默认解释成手工委托。

## 当前部分退出：价格条件卖出

官方手册确认价格条件单支持触发价格、买卖方向、委托价格方式以及委托股数／金额。价格达到预设条件即可发出委托，不要求额外填写网格上涨百分比或回落百分比。[价格条件单官方手册](https://m.touker.com/brochure/brochureh5/homeConditionDetails.htm?id=26)、[价格条件参数说明](https://cdn01.touker.com/hbec/projects/qq/production/conditionH5/explainH5/price.html)

| 报告含义 | 平台映射 | 取值原则 |
| --- | --- | --- |
| 当前评估部分退出 | 价格条件单 | 与旧双向网格分开安排 |
| 卖出条件 | 触发股价、卖出方向 | 使用本批 `partial_sell_plan.reference_price`，不再追加上涨幅度 |
| 数量 | 委托股数 | 使用经过当日回转规则、底仓及其他卖出计划校验的部分卖出份额 |
| 申报价 | 委托价格方式 | 单独列明限价或即时价格方式，不把触发价格写成保证成交价 |
| 报告出售预算 | 单独的策略约束 | 本批仅保留一条对应退出条件，成交后不自动重建 |

例如历史回归案例 `159687` 的当前参考价为1.913，部分退出方案为1000份，可展示「价格条件卖出：触发价1.913，委托1000份」。这是参数映射示例；正式报告必须换成本批行情及库存推导结果，不能继续沿用历史价格。

实际创建时，应核对平台显示的触发比较方向与本次意图一致。当前价格随时可能改变，不能仅凭报告中的单次快照宣称条件已经触发。

### 单笔份额与累计保护的边界

官方价格条件说明列出委托股数，未列出「最大卖出数量」或「循环次数」字段。因此：

- 可以明确安排一条委托1000份的价格条件卖出方案。
- 「只保留一条、成交后不自动重建、重复生成报告沿用原计划标识」是本项目的计划约束，不能伪装成平台已有开关。
- 不能在价格条件单的配置表中编造「最大卖出1000份」字段，也不能声称本次已验证所有平台版本的单次触发及自动重试行为。
- 新退出条件生效前，应按报告处理同标的重叠条件。暂停监控不能被写成已经撤销其此前发出的未成交委托。

## 等待上涨后回落：独立回落卖出

官方回落卖出手册明确分为启动价格和累计回落幅度：价格达到启动值后开始监控，随后从实际最高价计算回落；委托侧另填价格方式及股数／金额。[回落卖出官方手册](https://m.touker.com/brochure/brochureh5/homeConditionDetails.htm?id=32)

| 本地字段 | 平台字段 | 映射 |
| --- | --- | --- |
| `price_plan.sell_trigger_price` | 初始价格／预期价格 | 启动回落监控的阈值 |
| `parameter_plan.sell_pullback_pct` | 累计回落 | 本地保留正幅度；平台说明要求负数，填写时转为负号 |
| `partial_sell_plan.candidate_quantity` | 委托股数 | 使用本批校验后的部分卖出数量 |
| `price_plan.sell_confirmation_theoretical_price` | 报告解释，不填平台初始价格 | 最高价恰等于启动阈值时的精确理论边界，以十进制字符串保存 |
| `price_plan.sell_confirmation_tick_price` | 报告解释，不填平台初始价格 | 该假设下首个满足回落比例的 0.001 元档位；`sell_confirmation_example` 保持同值 |

设启动阈值为 `A`，激活后实际最高价为 `H`，回落幅度为正数 `r`，则精确理论边界为 `H × (1 − r / 100)`。`A × (1 − r / 100)` 仅是假设 `H=A` 的示例。报告将理论边界向下取至 0.001 元，得到按精确比例首个满足条件的档位；不使用普通四舍五入。不能把理论边界或确认档位填入初始价格，否则会重复扣减回落幅度。[累计回落参数说明](https://cdn01.touker.com/hbec/projects/qq/production/conditionH5/explainH5/down.html)

例如启动价为 0.721、回落为 0.46% 时，假设最高价停在启动价，理论边界为 0.7176834，首个满足比例的档位为 0.717 元或以下。0.718 元仅回落约 0.4161%，不能显示成已满足 0.46%。买入反弹侧方向相反：从假设低点计算理论边界后向上取档。`confirmation_price_basis=EXTREME_EQUALS_TRIGGER` 明确这是假设示例；平台实际极值、内部舍入及最终申报价没有因此得到验证。

该页面还说明「保底价触发」可优先于回落条件启动委托。需要保留先上涨、再从峰值回落的方案时，不默认开启该功能；开启时必须单独解释策略变化，不能仍声称只有累计回落满足才卖出。[保底价触发官方说明](https://gupiao.touker.com/stock/answer/173)

`WAIT_REBOUND` 适合映射到上述回落卖出条件。`CURRENT_PARTIAL_REVIEW` 若选择当前价格退出，则使用价格条件卖出，不机械沿用额外上涨阈值。

## 多次分批出货：明确首笔阈值和总量

官方分批出货手册确认支持初始价格、每次涨跌间隔、每笔委托股数／金额以及最大卖出股数／金额；它会反复分批执行到预设出售上限。[分批出货官方手册](https://m.touker.com/brochure/brochureh5/homeConditionDetails.htm?id=33)

参数说明要求最大卖出数量为100的倍数，且不能小于每笔委托数量。若确需这种类型，可以将每笔数量与最大卖出数量都设为本次部分退出量；总量不得覆盖仍需保留的库存。该「最大卖出」是分批出货的已核实字段，不能移植为价格条件单或回落卖出的既有字段。[分批出货参数说明](https://cdn01.touker.com/hbec/projects/qq/production/conditionH5/explainH5/batchClear.html)

分批出货的首笔触发还包含间隔：初始价格 `A`、上涨间隔 `p` 时，首笔阈值为 `A × (1 + p / 100)`。将当前价格直接填为 `A`，再填3%的上涨间隔，就仍然要求当前价继续上涨3%，不能把它称为当前退出。[首次触发价官方说明](https://gupiao.touker.com/stock/answer/19)

官方另确认分批出货可以选择上涨或下跌间隔。因此「分批出货只支持继续上涨」也不准确。不过，公开参数区间不等于已验证0%间隔可以实现立即触发；当前退出应优先使用已核实的价格条件字段，而不是依赖0%技巧。[上涨／下跌间隔官方说明](https://gupiao.touker.com/stock/answer/246)

## 计划复核与回归要求

- 当前退出的价格条件不得重新叠加网格上涨幅度。
- 回落卖出的启动阈值与确认价示例分开；从实际峰值回落，不能用单次快照声称路径已经发生。
- 理论边界保留精确十进制；买入反弹向上取档、卖出回落向下取档，恰好处于档位时保持原值。展示档位必须满足原比例，且相邻的提前一档仍不满足。
- 本地正回落幅度转换为平台负值，保留原值，避免两次取反。
- 计划总出售量不得超过本批允许的部分卖出库存；同标的多条计划共同使用一个出售预算。
- 价格条件／回落卖出不生成未核实的最大量或循环开关；分批出货的最大量必须不小于每笔量，并满足库存保护。
- 重复生成报告不等于重复新增条件；应根据现有条件标识安排沿用、修改或替换。
- 条件触发、委托提交、部分成交及全部成交分别记录；触发不是回款，未成交回款不能用于下一条买入条件的预算。

本次本地监控列表只保存13条网格和2条分批建仓，没有分批出货或价格卖出创建页截图。上述字段支持来自官方公开说明；实际页面布局、控件名称及设置结果仍须在执行页面对照，不把解析器中的正则表达式当作平台能力证据。

## 已委托页与当前占用

Touker「已委托」包含历史已成交、已撤单、申报失败及尚未显示终态的记录，不能把页签名称直接翻译为未成交占用。「监控中」条件也不等于已申报委托。用户没有手动委托，不排除条件触发后存在等待成交的阶段。

`touker_submitted_audit_v1` 保存采集时刻、实际选中状态、读取完整性和逐条原文；分析层区分终态、当日非终态、历史未更新状态及未知冲突。已成交与历史失败不重新扣现金或库存；旧日期的「已申报」仅证明平台旧状态未结束，不能据此认定今天仍冻结。详情与列表矛盾时保留两份证据，不自行选一个有利状态。

超长历史未读到底时明确记录实际范围及 `complete=false`，不声称全历史没有未成交单，也不因此抹掉自动同步账本中的已知现金和结算可卖量。附加委托证据进入原始数据指纹及本轮AI复核，证据变化必须重新复核。替换原单前仍处理当时已触发委托，防止重复报单。
