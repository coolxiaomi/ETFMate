# Skill 与产品契约

Skill负责入口路由、真实采集流程、AI复核与默认发布；产品规则以investment-plan、sell-policy、rule、action、grid、report和data-quality文档为准。

当前契约为`etf_account_transition_v10`：4只指定目标、低频波动与分批建仓、成长40%/价值60%、非目标旧仓退出、最终清仓不亏；最终组合通过管理旧仓、回收资金逐步达到。已移除自选池采集和独立T网格分析。

明确讨论、分析标的选择或修改skill时不自动采集发布；运行分析/报告的快捷口令默认完整实时采集并ShareOne发布。明确本地或不发布则遵守。

正式运行必须真实同花顺/Touker登录态和完整滚动证据，行情只覆盖规定范围。当前AI和分析版本必须一致。测试、演示或历史复用不能称作当前真实账户报告。

v8正式报告必须有本轮run_id/review_id/输入指纹绑定的逐只AI复核，未解决冲突阻断。分析完成后等待宿主AI写入、ai-attach与report，不再输出未复核的正式HTML。当前退出、未来网格与执行前缺口分开展示；完整日技术样本及实时报价分别标时，非网格监控条件单也纳入资金冲突复核。

修改规则要同步Python、聚焦测试与对应docs；修改入口/采集范围/版本要同步SKILL.md、agents/openai.yaml和运行检查清单。不提交账户数据或测试预览，不自动改真实条件单或交易。

## v9补充

固定账户事实包括不追加或转出、无额外手动委托、Touker成交自动同步账本。按可验证公式给出现金、保护线额度和T+0/T+1可卖量，不再复制“全部未知”。全部条件单统一测算资金压力，库存约束及条件单映射进入AI输入指纹和质量闸门；旧v8分析需重跑，不能只改契约字符串。

## v10决策复核

确认价采用十进制比例与方向取档，买入反弹向上、卖出回落向下；理论边界、满足条件的报价档位与实际成交价分开。`decision_review`明确尚未确认的账户风险、退出期限、角色预算和回款用途，`action_plans`记录逐只数量依据、减持比例与未触发后的复评路径。委托失败按已观察原文归类，部分成交、失败、未成交及新旧单替换使用独立后续处置。

分析与AI均升级v10；旧v9分析不能直接重渲染，已明确披露的政策缺口不能被AI解释成交易授权，也不能仅因缺口而禁止既有规则允许的部分卖出。净收益与回撤有效性尚未验证。开发预览保留历史快照时间，不使用旧AI、不冒充最新实盘报告。
