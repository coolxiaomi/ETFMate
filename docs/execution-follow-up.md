# 条件单成交与替换后的复核

本契约补充[条件单执行映射](conditional-order-execution.md)，用于报告与 AI 输入。它描述计划在部分成交、失败、等待和替换后的复核要求，不新增真实平台功能，不修改原有买卖数量、资金优先级或本金约束。

## 已读取委托的失败原因

`submitted_orders.failure_summary.contract=submission_failure_summary_v1`。仅统计来源、日期和状态可核验的 `TERMINAL` 且 `REJECTED` 记录；列表与详情冲突、撤单失败和日期无效记录不作为确定的申报失败原因。

| 分类代码 | 含义 | 原文依据 |
| --- | --- | --- |
| `INSUFFICIENT_FUNDS` | 资金不足 | 明确的「可用资金不足」或「资金不足」错误 |
| `INSUFFICIENT_SELLABLE` | 可卖数量不足 | 明确的可卖量、股份或库存不足，以及「委托数量超出该证券……的可用数量」错误 |
| `INVALID_PRICE_OR_PARAMETER` | 价格或参数不合法 | 明确的价格、数量、参数错误，以及 100 整数倍限制错误 |
| `UNCLASSIFIED` | 未归类 | 失败结果没有可识别原因，或列表和详情给出不同原因 |

分类使用原始状态、详情状态和明确的错误原因字段，不从任意页面原文中的帮助、否定或假设句推断原因。每类保留全部所见笔数及最多 3 份原文示例，示例带证券代码、日期、原单标识与证据字段。原始记录不改写。未读取的历史不能补为 0；来源无法核验时，失败笔数为 `null`。

`scope=OBSERVED_RECORDS_ONLY` 始终保留。完整性标记和实际读取日期范围随摘要输出；部分历史也可呈现所见失败，不称为全部历史失败总量。失败笔数不是交易亏损笔数，历史失败占比不能称为亏损率或未来失败概率，也不能证明当前现金或库存仍不足。

有 `submitted_at` 或完整 `date`、`time` 时，统一转换为上海时区并与 `captured_at` 比较。同日但时刻晚于采集的记录归入 `unknown_orders`，在 `issues` 中保留原因，不进入已确认失败笔数或 `status_counts.REJECTED`。两组时间证据矛盾时不自行选取。仅有日期时保留 `observed_time_basis=DATE_ONLY` 和日级判断限制，不补造零点或采集时刻；有完整时刻时为 `TIMESTAMP`，归一化值保存为 `order_timestamp`。

## 监控冲突与待核对条件

`live_order_conflicts` 仅记录明确的买入限制冲突：已监控的双向网格或分批建仓与本批次暂停新增买入判断不一致。停用数量只统计这些已确认冲突。

`condition_review_items` 单独列出待核对项，不自动要求停用。`SELL_OVERLAP_REVIEW` 表示同代码已有卖出条件且本批次也有卖出候选，需确认是否沿用原单及出售预算是否重叠；`UNKNOWN_CONDITION_TYPE` 表示类型或方向尚未明确；`GRID_PLAN_REVIEW` 表示新草案受限，尚不能推断原单参数也冲突；`MISSING_DECISION_REVIEW` 表示本批次缺少同代码判断。报告分别展示已确认冲突和待核对原因，不能仅因条件未纳入网格决策就归为买入冲突。

## 成交、失败与等待

每份 `condition_plan` 和账户级 `execution_review` 均输出 `follow_up_policy.contract=condition_follow_up_v1`。五类事件统一提供 `label`、`status` 和 `actions`，便于报告和 AI 使用同一说明。

1. `partial_fill`：按实际成交数量和金额核对自动同步后的账本现金、持仓、可卖量与剩余净投入。未成交部分不计回款；已同步回款不得再次累加。先确认剩余委托状态，不按原委托总量重复新建。
2. `rejected`：先核对原单标识、原始回报和原因。申报失败与撤单失败分别处理。原因及原委托终态明确后刷新账户和报价，再复评计划；`automatic_retry_allowed=false`。
3. `unfilled`：先区分条件监控、已触发报单和部分成交，再核对活跃委托及撤单回报。没有已核实的时限和平台设置时，`automatic_timeout_cancel_allowed=false`，不能补成超时撤单或自动追价。
4. `replacement`：核对原单标识与已报委托；停用重叠监控后确认原委托的成交或撤单回报；再按实际现金和库存复评替代单。保存后核对新单参数及实际监控状态。`zero_gap_guaranteed=false`，不承诺无监控空窗。
5. `revalidation`：报价、账户、参数或原单状态变化时刷新证据并重新计算。有效期、超时撤单与滑点／价格偏差保护须核对平台实际支持及本单设置，不生成未经核实的时长或偏差值。

`follow_up_policy.execution_authorized=false`。这些字段是本地复核要求，不能作为已下单、已撤单、已启用新监控或自动重试的证据。部分成交与失败回报也不直接写入现金或库存，资金及库存继续由原有账本与交易制度模块推导。

## 回归边界

测试覆盖明确错误的分类、原文保留、部分历史、来源缺失、撤单失败、状态冲突、帮助文字、原因冲突、部分成交后防重复、替换顺序和未经核实的平台参数。测试通过证明本地契约一致，不证明真实平台成交行为、策略收益或执行已完成。
