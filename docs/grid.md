# 低频非对称条件计划

指定目标的波动交易以隔日或每周数次为频率目标；不保证频率。原自选池T网格候选模块已退出当前流程。

## 参数候选

ATR使用本次行情的ATR14百分比。下列系数为起始启发式，未经收益最优性或触发频率回测，不当作用户确认的固定参数。

| 角色 | 买入下跌百分比 | 卖出上涨百分比 |
| --- | --- | --- |
| 510500低频波动 | max(2,1.4×ATR) | max(1.5,1.2×ATR) |
| 赛道与成长价值建仓 | max(3,1.8×ATR) | max(1.5,0.9×ATR) |

买入反弹为clamp(0.15×ATR,0.15,0.8)，卖出回落为clamp(0.10×ATR,0.10,0.6)，单位均为%。两者独立，不再强制相等。

保留有效现有基准价，无基准时用现价作参考；偏离现价超过两倍最大触发间距标记待复核，不自动重置。先计算并取档启动阈值，再以该阈值作为假设低点或高点计算确认价。买入反弹确认向上取档，卖出回落确认向下取档；具体公式见本文「确认价边界与交易档位」。这些示例不等同于路径依赖条件单的保证成交价。

## 数量与资金

候选数量优先读取Touker合法两侧单笔量，缺侧数量才回退共用数量；0、1、不足100或非100整数倍均不得解释成停用。缺失或异常时，卖出按实际持仓约1/4向下取整至100、最低100起拟，买入按100起拟，并记录来源。卖出动作候选不能穿透建议底仓；目标仓保留至少一半库存向上取整至100，并尊重更高的原底仓。小仓位仍有参数草案，但没有可执行卖出数量。

逐步建仓时买入候选数量至少为卖出候选的2倍，这是待预算核验的起始方案，不保证净买入。缺少单笔量时的100份仅为平台最小数量起拟，不冒充实际设置或已核验执行量。所有买入建议仍需满足全账户预算、现金、冻结和网格累计占用约束；仅在已设置最大持仓时应用该固定上限。

`candidate_buy_quantity/candidate_sell_quantity`是候选；`suggested_buy_quantity/suggested_sell_quantity`为已核验执行数量，当前统一资金与可卖量尚未完成核验，执行数量留空且`grid_applicable=false`。报告的「建议份额」读取独立的 `parameter_plan` 双向草案。风险、80%总仓位、库存或最大仓等限制作用于整单，不存在单侧暂停；不得用0份实现停用。

## 清仓保护

普通部分卖出允许低于成本，已亏损目标不因此自动暂停所有波动卖出。循环卖出必须由平台最低底仓保护；无法保证时整单停用，部分卖出另行安排。每次成交后更新本轮净投入，最终清仓按[sell-policy.md](sell-policy.md)单独核验。非目标持仓仍给出过渡期部分卖出及先卖后买的条件回补计划；回补不自动扩大旧仓，不与目标建仓重复占用回款。

报告仅提供修改建议，不自动操作Touker。

## 现有待退出持仓

现有非目标仓同样生成ATR波动幅度、反弹分批卖出价和候选数量，不能提前return只给清仓提示。新过渡计划以当前价为候选基准，调整实际旧网格需另核验。卖出数量优先沿用原网格数量，缺失时按实际持仓约1/4取整，候选最低库存至少100份，并尊重更高的已设底仓，避免自动清仓。

正常行情下可给出先卖后买的回补方案：候选回补为卖出候选的一半向下取整至100份，待实际卖出、资金分配及仓位核验。回补金额不超过分配给它的实际可用回款，份额不超过实际已卖量，不扩大旧仓；风险高时暂停回补，仍保留反弹卖出计划。上述比例是分析起始候选，不是用户固定参数或盈利承诺。

建议先管理现有仓，再将释放的资金转给目标；旧仓退出与目标建仓不是立即一次完成的切换。

## 可选底仓上下限（2026-09-08 用户确认）

未设置最小底仓或最大持仓表示不设对应固定限制，不代表漏配、必须核验或无限可用资金。模型字段仍为 `None`，不以 0 替代；显式 0 是已配置数值。报告分开展示当前设置与策略建议。`current_min_base_quantity/current_max_position_quantity` 保留平台值，`min_base_status/max_position_status` 区分 `UNSET/CONFIGURED`。

本次保留量继续沿用角色策略：目标仓建议保留至少一半库存，旧仓分批退出建议保留至少100份，随持仓变化重新计算；它是可调整建议，不冒充用户固定下限。显式更高底仓同时约束目标仓与旧仓卖出。最大持仓未设时不增加固定上限；已设时买入建议按剩余额度向下取整至100份，旧仓回补按建议卖出后的额度计算，并须在实际成交后重算。

本次没有引入自动预算分配或自动调整平台设置。80%组合保护上限、可用资金与可卖量、累计占用及最终清仓不亏约束继续适用。ATR提供价格间距起点，v6再按综合技术状态修正；单笔数量缺失时明确标记起拟依据，不能从「不限」推导出无限份额。

## 综合指标对参数与执行的影响（v6）

先按本文角色公式计算并保留 `parameter_basis.original`，再按 `technical_assessment.status` 修正：

| 状态 | 修正草案 | 执行条件 |
| --- | --- | --- |
| 弱势、超卖未企稳、过热 | 买入下跌×1.25、反弹×1.5（上限0.8%）；卖出上涨×0.85（下限1.5%） | 禁止新增买入与回补，整单不启用；部分卖出另行核验 |
| 超卖后初步修复 | 反弹×1.25（上限0.8%），不缩窄下跌间距 | 回落后复评，仍受全部账户和风险限制 |
| 趋势偏强、信号分歧、数据不足 | 保留ATR起始间距 | 偏强与分歧可保留条件买入候选；数据不足仍阻断 |

卖出回落比例沿用ATR起始公式，数量仍由角色、现有单笔量、底仓及上限决定，不按技术评分自动放大。修正后下跌间距达到100%时拒绝生成参数。报告逐标的展示ATR和修正原因；`parameter_basis.technical_status` 与规则状态必须一致。这些系数未经收益验证，不能称为最优网格。

## 双向平台契约（2026-09-08 用户纠正）

Touker网格的买、卖均≥100份，使用100的整数倍，且无法单独暂停买或卖。`parameter_plan` 保存买入下跌、反弹、数量及卖出上涨、回落、数量六项完整参数；即使当前受限，也保留复评草案。行情无效或无仓旧标的退休时不编造参数，仅显示整单停用原因。

`grid_execution_status` 仅为 `DO_NOT_ENABLE` 或 `PENDING_VERIFICATION`；后者仍非执行许可。`buy_execution_status/sell_execution_status` 只表示内部动作限制，不表示平台单侧开关。原单数量异常、基准偏离、已停用、风险、组合上限、库存或固定上限不足时整单不启用；缺资金及库存核验时等待核验。不得自动改单。

旧仓「先卖后回补」依赖真实回款，不能伪装为可自动运行的双向网格。报告同时列完整参数草案与独立分批计划，回补动作候选仍按已卖量、回款和风险限制。候选回补不足100时保持无回补动作；草案的100仅供未来复评。策略建议的最小仓与平台当前值分列；未设上下限不显示任何占位。

本次问题复盘：批次 `20260908-084148` 的同花顺持仓为510500持1000，Touker采集文本为单笔买100、卖1。旧逻辑把卖1向下取整为空，并与「停用」混写；买入受该批次总仓90.83%及高风险共同限制。异常单笔量不能代替持仓，也不能推断平台已停用；新逻辑保留原值、另算数量草案、明确整单限制。该复盘不证明平台当前设置或实际可卖量。

## 行动展示与执行状态（v7）

MIXED不再单独触发整单不启用；高风险、数据、资金、仓位和库存条件继续校验，具体条件见score.md。无持仓目标可以保留未来买入候选，但没有卖出动作或可直接运行的双向网格。报告展示「等待回落，分批建立底仓」及「建仓后再评估卖出」，不以无库存否定建仓阶段。参数草案仍为合法双向六项，执行数量保持未知。

`grid_execution_status/grid_execution_note`保留内部复核信息，报告不逐卡拼接其长提示。原单开关以新增`current_enabled`记录的真实采集状态描述；不能把DO_NOT_ENABLE解释为已经停用平台。基准偏离、原单异常、最大仓余量不足及底仓不足继续在对应卡片显示。

## 当前退出与路径价格（v8）

`partial_sell_plan` 单独保存当前部分卖出判断及参考价、候选数量、卖出约束。当前退出评估使用实时价；`first_sell_reference_price` 等字段仍是未来网格的确认价示例，不成为当前退出的额外上涨前提。

`price_plan` 明确基准来源、两侧触发价与确认价示例。买入先到下跌阈值，再从实际低点反弹；卖出先到上涨阈值，再从实际高点回落。快照只能说明当前是否处于阈值区域，`path_evidence=SNAPSHOT_ONLY` 不证明路径、委托或成交。参数表称“确认价示例”，不称保证首笔价格。即使沿用真实原单基准，拟议幅度也不等于真实原单参数。

整个账户保留全部监控中条件单的冲突核对清单，包括非网格的分批建仓单。非网格不参与网格建议，仍须计入潜在资金占用核对。报告不把规则中的禁止启用状态当作平台已暂停，不自动修改平台。

## 可配置价格与库存（v9）

触发价按ETF的0.001档位统一计算：下跌买入阈值向下取整，上涨卖出阈值向上取整，避免提前触发；确认示例从取档后的阈值计算，并按下文 v10 规则取确认档位。正文、参数草案与条件单配置共用启动阈值，不另行四舍五入出不同初始价。即时买一仅用于本次部分卖出；最终清仓固定限价取本次有效报价与已核验回本线的较高者，再向上取档，不能因本金已回收就填0.001或远低于市场的无效申报价。基准与百分比用十进制计算，避免浮点误差使恰好位于一档的价格多进一档。

可卖量来自inventory_plan，先约束单笔卖量再评估部分卖出政策；资金状态来自funding_plan。已有现金与制度可卖量有明确计算结果时，不再保留笼统的库存/现金未核验说明。候选双向参数仍不意味着能够用0份实现单侧暂停。

## 确认价边界与交易档位（v10）

理论边界与可满足比例的交易档位分别保存。假设激活后的实际低点或高点恰等于对应启动阈值 `A`，买入反弹比例为 `b`、卖出回落比例为 `r`：

- 买入理论边界为 `A × (1 + b / 100)`，首个满足条件的档位向上取至 0.001 元。
- 卖出理论边界为 `A × (1 − r / 100)`，首个满足条件的档位向下取至 0.001 元。
- 恰好位于交易档位的边界保持原值。不得先四舍五入理论边界，再决定是否满足比例。

`price_ticks.confirmation_price` 使用 `Decimal` 计算。`price_plan` 保存以下字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `buy_confirmation_theoretical_price`、`sell_confirmation_theoretical_price` | 十进制字符串 | 保留计算得到的完整小数，不经过四位或六位小数舍入 |
| `buy_confirmation_tick_price`、`sell_confirmation_tick_price` | 数字 | 首个满足确认比例的 0.001 元档位 |
| `confirmation_price_basis` | 字符串 | 固定为 `EXTREME_EQUALS_TRIGGER`，明确实际极值等于启动阈值的示例假设 |
| `price_tick` | 数字 | 固定为 `0.001` |

兼容字段 `buy_confirmation_example`、`sell_confirmation_example`、`first_buy_reference_price`、`first_sell_reference_price` 与对应确认档位保持一致。未来部分卖出参考价也使用卖出确认档位；当前部分退出继续使用实时报价。

批次 `20260908-121824` 的通信 ETF 示例说明了旧问题：`0.721 × (1 − 0.46 / 100) = 0.7176834`，普通三位小数展示为 0.718，实际回落仅约 0.4161%；按精确比例首个满足条件的档位应为 0.717。买入侧存在相反方向的同类问题。因此报告需分别展示启动阈值、理论边界、确认档位与该示例假设，不能把确认档位填入平台的初始价格。

上述计算只保证示例档位满足项目声明的精确比例。实际条件单从激活后实际极值计算，平台内部比较与舍入细节仍需核验；触发、申报和成交保持区分。
