# 账户角色与动作契约

当前契约为 `etf_account_transition_v10`，账户模式为`ROLE_BASED_ACCUMULATION`。角色先于趋势评分决定方向；技术评分、综合量价条件与硬过滤影响风险和是否暂停新增投入；综合状态同时修正参数草案，不改变角色预算。

| 角色/情形 | 动作状态 | 执行含义 |
| --- | --- | --- |
| 目标等待回落 | WAIT_DIP | 低频波动或逐步建仓，不立即买入 |
| 风险或仓位限制 | WAIT_BUY_REVIEW | 暂停新增投入，保留风险提示 |
| 组内高配侧 | WAIT_PAIR_BALANCE | 暂缓新增，等待低配侧回落，不强制卖出 |
| 现有待退出持仓 | MANAGE_EXISTING | 持有、反弹分批回收、受控回补及最终退出，清仓核验单独处理 |
| 清仓参考条件满足 | LIQUIDATE_CONDITIONAL | 仅清仓候选，执行前复核限价和库存 |
| 无持仓旧网格 | RETIRE_GRID | 停用该标的整个旧网格，不复活为建仓候选 |

159781不是最终波动配置目标，但现有持仓仍接受波动改善与逐步退出建议。受控回补需要真实卖出回款，不自动扩大旧仓；弱趋势不能导致自动亏损清仓。高风险保留风险目标仓位0，建议执行后仓位仍为当前仓位，调整量0，避免把期望与未执行计划混用。

全账户角色预算未知时`target_position_ratio`为空，不把组内40/60写成全账户仓位。`action_quantity`留空；`candidate_liquidation_quantity`只在清仓参考条件成立时给出。网格候选数量与执行数量分别记录。

资金仓位口径降级为持仓市值占比时，不冒充账户总资产仓位触发硬上限。可用现金、冻结和条件单占用未核验时不直接安排新增资金。

资金优先级为 `LEGACY_RECOVERY_FIRST`：先安排待退出 ETF 的回本管理资金，目标组合仅使用 `VERIFIED_SURPLUS_AFTER_LEGACY_RESERVE`。`allow_existing_cash=true` 表示可使用满足优先安排后的现有余款，不代表可以抢占旧仓资金。资金优先级不改变价格、风险、仓位或清仓约束。

网格动作按整单执行限制表达。内部买卖状态不是平台开关；完整双向参数草案、动作候选与核验后执行量分离，见grid.md。

综合技术条件以score.md为准。超卖未企稳、过热、弱势或数据不足时目标进入WAIT_BUY_REVIEW，旧仓暂停回补并保留反弹部分卖出；初步修复不能覆盖高风险与资金限制。

v7报告按行动阶段展示：INITIAL_ENTRY（未持仓目标先看分批建仓）、POSITION_MANAGEMENT（已有目标仓）、LEGACY_MANAGEMENT（旧仓卖出回补）、RETIRED（无仓旧标的）和WAIT_DATA（无有效价格参数）。analysis/action_plan.py统一生成报告和AI使用的说明，不赋予执行权限。账户保护线只在总览说明；原内部整单状态继续保留，但不直接用其长提示作为逐卡行动标题。

## 当前动作与后续参数（v8）

`action_plan.contract=actionable_review_v1`。动作按持仓、退出条件、买入硬限制和价格路径分别判断，不能用“旧仓有卖出数量”统一生成等待反弹。

- 旧仓现价达到页面成本参考，或出现过热时，进入 `CURRENT_PARTIAL_REVIEW`，以当前报价评估部分退出。页面回本不证明完整持仓周期不亏，最终清仓核验独立保留。
- 已有目标仓过热时同样评估部分卖出，保留既定底仓；不能因目标角色忽略当前卖出判断。
- `LIQUIDATION_REVIEW` 使用已核验清仓回本条件、当前价格和全部库存，独立于 ATR 网格参数；仍须核对实际可卖量和有效限价。
- 本次草案上涨阈值已被现价越过时为 `REVIEW_PATH`，核对实际峰值回落，不能继续写“等待上涨”，也不能推断真实原单触发或成交。
- 未到退出条件的旧仓保留 `WAIT_REBOUND`。无可卖候选、无持仓及行情无效分别显示，不生成虚假卖出份额。
- `buy_status=BLOCKED` 时正文明确本批次暂停买入或回补，当前买入数量为空；未持仓目标标题也必须体现限制，不能由“逐步建仓”覆盖。

每张卡片先给本次动作、参考价、候选数量、触发条件与成交后重算要求，再展示可展开的双向参数草案。候选数量继续沿用既有单笔量和底仓规则，不因这次修复擅自扩大预算或加快清仓。

## 资金、可卖量与条件单配置（v9）

当前报告接收 `funding_plan` 和逐代码 `inventory_plan`。单笔部分卖出同时受策略保留量、已配置下限与按T+0/T+1推导的可卖量约束；今日不可卖不再误写为底仓不足。清仓可卖量不足时不得截断数量后仍称全部退出。

动作输出 `condition_plan`：当前部分退出对应价格条件单卖出，不附加下一格上涨；等待反弹对应独立回落卖出，初始价取上涨激活阈值、累计回落取负数，关闭保底价触发。ETF价格按0.001向上取整激活价；路径示例不是盘口成交价。同标的先停原网格及重叠卖出单，已报委托结果明确后再启用替代单，成交后不自动重建。报告只提出配置，不操作平台；详情见[条件单执行映射](conditional-order-execution.md)。

最终清仓与回补互斥：进入`LIQUIDATE_CONDITIONAL`即阻断买入/加仓，`LIQUIDATION_REVIEW`不保留回补数量或双向网格展示；成交后不重建旧仓。全清固定委托价取本次有效参考价和已核回本线的较高者向上取档，避免本金已收回时给出接近0的无效申报价，且不得用即时买一价绕过本金底线。

## 决策边界与后续处置（v10）

`analysis/decision_review.py` 输出账户级 `decision_review_v1`，与行动计划一起进入分析、AI 复核和报告。80%明确表示新增买入门槛，达到后暂停新增投入；它不是强制立即减仓规则，也不代表账户最大回撤或本金保障。账户风险限额、四只目标的账户预算、现金缓冲、旧仓预留与回款分配、退出复核期限分别记录为未确定项，不凭空补入数值。这些缺口不阻断符合现有规则的部分卖出复评。

最终清仓回本继续作为既定硬约束。亏损部分卖出可能提高剩余回本线；在该约束下，旧仓退出可能长期不能完成，不能把四只目标组合表述为必然按期实现。费用按既有约定忽略，ATR 参数、数量和风险提示均不构成净收益或回撤验证。

每个 `action_plan.quantity_basis` 记录原始卖量、合法原单量或约1/4持仓起拟的来源、本次建议份额、持仓减持比例及可核实的账户权重，保留 `risk_optimized=false`。持仓市值占比不得冒充账户权重。数量仍受保留仓与可卖量限制，不因报告增加解释就改变候选份额；过热只是部分退出的复评依据，不证明理想卖点。

`action_plan.contingency_plan` 使用 `REASSESS_ONLY`：未到卖出启动价、继续下跌或长期未触发时，刷新完整日信号、报价、库存和账户风险再复评。复核期限未约定时为空，不自动加仓、改价、延期或绕过清仓约束。部分成交、失败、未成交及替换原单的委托处置另由 `condition_plan.follow_up_policy` 表达。

账户卖出情景仅逐笔推演当前部分退出或已核验清仓，不合计未来反弹计划。`valuation_basis=LEDGER_VALUE_WITH_REFERENCE_SALE`：按本标的账本市值/持仓计算卖出份额的原账面价值，按计划参考价估算回款，差额计入情景总资产，剩余持仓保留账本估值。这样即使报价晚于账本估值，也不混用两种市值。情景忽略费用，不是已成交账目；未知现金或估值保持为空，回款不自动分配给旧仓或目标。
